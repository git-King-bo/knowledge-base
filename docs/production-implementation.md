# 团队部署实施与验收

本轮按单服务器、一个团队实施。现有数据已保留，生产域名、外连白名单、异地备份位置和告警接收方需在目标环境配置。不能把本地测试成绩当成公网容量承诺。

## 已实现

| 项目 | 实现位置与行为 |
| --- | --- |
| 登录与角色 | `auth.py` / `security.py`：密码 scrypt、随机会话令牌仅存哈希、HttpOnly Cookie、CSRF 验证头、登录限速、账号停用与会话注销。管理员、编辑者、只读角色，按知识库授权。 |
| 密钥保护 | Fernet 加密，旧明文密钥迁移。变更模型地址需重新提供密钥。生产模式要求 HTTPS 与精确域名白名单，默认拒绝本机和私网地址。应在主机防火墙继续限制出站流量。 |
| 秒传与复用 | 浏览器计算 SHA-256，服务端只返回用户有权读取的文件命中。正常上传仍由服务端重算摘要。复用条件还包括解析/切片/向量配置指纹、完成状态、文件存在和数据版本；人才被编辑后不会把修改结果冒充原始文件。没有重复付费向量请求。 |
| 后台任务 | SQLite 持久队列、单工作线程、跨进程文件锁。解析放在有超时的子进程，解压上限 100MB、文本上限 500万字符、人才上限 2万条。任务进度、重试、取消；服务重启重新排队未完成任务。向量每批持久化，重试跳过已完成批次。 |
| 人才工作台 | 独立人才列表、分页、姓名/机构/领域查询、完整字段详情、CSV 导出、同名检测、编辑冲突检查、变更历史。上传前可预检记录数、字段和同名数量并确认。上传 XLSX 自动识别姓名列，保留未知列和公式。人才查询及全表数量优先读数据库。编辑后排队更新索引，旧版本切片在更新完成前不参与检索。 |
| 限额 | 用户分钟请求限流、每日模型请求数、Token预算保守预留、推理并发上限、队列长度上限、上下文长度及模型输出 Token 上限。未知用量保守计费；进程崩溃的未结算预留不会自动退款，避免误放大预算。向量任务按批次预留。 |
| 查询与引用 | 切片分页；向量解码和归一化矩阵使用有容量限制的缓存与向量化计算；回答采用本轮唯一引用编号。续写从服务器重新查询知识库证据。仍属于单机精确扫描，不宣称支持百万向量或多副本。 |
| 生命周期 | 删除知识库进入回收站，恢复或管理员彻底删除；共享资料只有在最后一个关联删除后清理。移除后未关联的资料有单独的管理员清理入口。SQLite 外键、WAL和 busy timeout。 |
| 运维 | 完整数据库/文件备份、校验清单、恢复至新目录、日志正文保留期清理、健康检查、运行状态页、请求ID、结构化请求日志。Docker/Caddy HTTPS部署文件、CI、依赖锁、定时备份模板、健康探针。 |
| 会话体验 | 登录用户的历史会话、刷新恢复入口、收藏与反馈；会话存储前/读取时检查引用知识库权限。 |
| OCR | 隔离解析进程支持调用 OCRmyPDF。需安装工具并启用 `APP_OCR_ENABLED=true`，容器构建参数 `INSTALL_OCR=true`；当前本机未安装该工具，未验证真实扫描件识别质量。 |

同名核对提供审计接口 `/api/talent-duplicate-reviews`，不会自动按姓名合并。数值人才字段保留原始文本，排名通过已校验的数值转换执行，不直接按字符串排序。

## 本地使用

1. 重启后端、前端开发服务。Vite 已代理 `/api`，同源 Cookie 登录，无须把模型密钥交给浏览器。
2. 用户名 `admin`，首次密码在 `backend/storage/security/initial-admin-password.txt`。文件权限为 0600，不在聊天和日志中打印密码。
3. 登录「账号与管理」修改初始密码，创建账号，分配知识库权限。密码变更会注销已有会话。
4. 「人才管理」浏览和编辑人才，「后台任务」查看进度，知识库上传自动进行哈希预检。
5. 初始账号只能读取有服务器文件权限的人拿到的随机密码，不存在默认公开密码。

现有「人才库-900」906条记录完整保留。另一份既有「新知识库」表格补录111条，目前合计1017条来源记录，不能跨来源直接当作1017个独立自然人。兼容性迁移确认7份资料可复用，4份旧资料保留但未宣称可复用。迁移未重新调用模型。

## 生产部署

- 复制 `deploy/production.env.example` 为 `deploy/production.env`，配置实际模型域名白名单、CORS和模型凭据。不要提交此文件。
- `SITE_ADDRESS=knowledge.example.com docker compose -f deploy/compose.yaml up -d --build`。域名需指向服务器，开放80/443；后端不直接暴露公网端口。
- 默认仅一个 API 进程和一个持久导入 worker；不要增加 `--workers` 或横向复制共享 SQLite。需要更大规模时再迁移关系数据库、任务调度和向量索引。
- 容器中初始密码位置 `/data/security/initial-admin-password.txt`。单独备份 `/data/security/encryption.key`，不要与数据备份放在同一个公开位置。
- `GET /ready` 检查数据库、上传目录和 worker 线程。`/api/operations` 供管理员查看任务和预算；`deploy/monitor.py` 可接现有告警平台，失败返回非零退出码。不会擅自发送邮件或通知。
- 主机部署可安装 `deploy/knowledge-maintenance.service` 与 `.timer`（修改实际路径与用户后启用）；容器部署从宿主机定时执行 `docker compose -f deploy/compose.yaml exec -T backend python scripts/maintenance.py`。
- 定时备份保存到本机，不等于异地灾备。将完成的归档推送到团队控制的备份存储，并设置访问控制和保留期限。
- 模型请求正文和回答默认保留30天；定时维护会清空更旧的正文，保留用量统计。备份可能仍包含旧正文，备份保留策略必须同步配置。

## 备份与恢复

在 backend 目录运行：

```sh
.venv/bin/python scripts/backup_workspace.py backup
.venv/bin/python scripts/backup_workspace.py restore --archive storage/backups/你的备份.tar.gz --target /新目录/恢复结果
```

备份使用 SQLite backup API，复制关联原文件，生成 SHA-256 清单。恢复校验全部内容且不覆盖已有目录。服务停止后，将校验后的数据库、文件以及单独保管的加密主密钥部署到对应路径，再启动服务验证。

本轮改造前归档为 `backend/storage/backups/before-production-implementation.tar.gz`。已实际恢复到临时目录并确认原有906条完整字段、全部切片和向量与当前一致。迁移脚本另生成了一份时间戳备份。
