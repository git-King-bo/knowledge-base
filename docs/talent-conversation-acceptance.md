# 人才多轮问答收尾记录

2026-09-29

## 已实现

- 人才名单、匹配数量、指标缺失数量、分页范围及 Record 引用由程序生成；模型仅参与意图理解和查询计划生成。
- 每轮结果返回结构化查询状态（知识库、检索问题、筛选和排序计划、分页位置），随会话保存并用于下一轮。
- “继续／下一页”重新执行当前可访问资料中的同一查询，按分页位置取结果，不再调用模型猜测下一页。
- 新增或修改筛选条件后从第一页查询；换知识库不会直接复用旧库分页。
- 未指定排序字段时不报告指标覆盖率；全部排序指标缺失时返回基本资料，明确不做排名。
- 人才每页条数独立于向量召回 Top K；问答页面提供下一页按钮。
- 旧会话没有分页状态时先要求重新建立查询；字段变化或原资料不可用时不继续猜测。
- 无法可靠生成查询计划时直接澄清，不让回答模型根据历史补充名单。

## 验收

使用本地现有906条记录及当前千问 API，实际执行：

1. 提取清华大学相关人才：匹配35条，展示5条。
2. 按 OpenAlex h-index 排序：8条有指标，27条缺失，展示排名前5条。
3. 继续：只展示第6—8条，标记无下一页。
4. 提取具身智能领域的：保留清华大学条件，返回5条基本资料，明确指标均缺失、不做排名。

自动化回归还覆盖末页重复请求、取消排序、跨库、旧会话、流式分页、前端查询状态传递和下一页按钮。

## 边界

本轮完成的是人才列表问答链路。复杂分析或复杂条件的意图理解仍依赖模型，不能据此宣称整个知识库已完成生产验收。分页每次查询当前数据，不是历史结果快照；分页期间修改原始人才资料可能改变结果位置。
