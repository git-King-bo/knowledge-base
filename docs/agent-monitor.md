# Agent 执行监控

入口：侧栏「Agent 监控」。可搜索历史对话标题，再选择对话与执行状态；左侧时间线在剩余可视高度内滚动，右侧显示请求概览。模型请求、响应和最终输出已合并进时间线。筛选汇总跨全部分页计算。

## 记录内容

- 请求 ID、历史会话 ID、对话轮次 ID、知识库、请求参数、用户问题。
- 实际执行的查询改写、人才查询规划与结构化检索、查询向量编码、知识库检索、联网检索、上下文组装、模型调用、开始输出、请求结束。
- 模型名称、调用输入和输出、每次调用耗时、输入/输出/总 Token、缓存命中 Token。
- 本次请求的输出、执行状态、错误、服务端从接收已验证请求到首次产生输出的耗时及总耗时。

时间线记录系统实际执行动作，不记录模型私有思维过程。嵌套阶段耗时不能相加。运行期间会显示执行中，结束后刷新查看完整步骤和消耗；不进行实时逐 Token 监控推送。

## 关联与统计口径

问答请求携带 `conversation_id` 和 `turn_id`；后端为每次请求独立生成 trace ID。续写沿用会话和轮次 ID，因此能查看同一轮的多次尝试；续写记录的输出是本次新增内容。

汇总包含查询改写、人才查询规划、Embedding 和回答生成的所有已记录模型调用。程序直接生成的人才分页结果不增加模型调用，也不虚构 Token。未上报 Token 标为未知，已知总量不代表全部用量；缓存命中是输入 Token 的子集，不重复累加。失败和停止保留已报告用量，未知用量不按字符数估算。请求预算预留量不是服务商实际消耗，未纳入此监控。

监控针对 `/api/knowledge/ask` 和 `/api/knowledge/ask/stream`。鉴权、请求校验和预算拦截发生在监控开始前；独立检索测试、导入索引和连接测试仍使用原 Token 监控。旧会话没有关联 ID，无法可靠补录之前的步骤和用量，显示无链路记录；继续旧会话后可查看新增请求。

## 访问和持久化

每个账号只能查询自己的记录，包括管理员。非管理员还需保有对应知识库权限；未指定知识库的跨库请求不向普通账号开放追溯详情。历史会话关联不能指向其他用户已保存的会话。不会记录 API Key 或认证请求头。

记录保存于 `agent_traces`，独立于已保存对话；删除会话不会清除监控记录。进程异常退出时尚未完成的记录可能保留“执行中”，不应据此视为成功或零消耗。

新增迁移 `0006_agent_traces`。后端重启时开发环境创建新表，生产环境按现有启动流程执行 Alembic 升级。未改变现有业务表数据。

## 验证

`backend/tests/test_agent_monitor.py` 覆盖会话关联、同步与流式完成、流式失败、停止、未知用量、分页汇总、人才程序分页、规划失败、跨账号隔离和撤权。

`frontend/tests/agent-monitor.test.ts` 覆盖历史筛选、未知用量提示及流式请求会话/轮次关联参数。

## 细化的实际执行路径

新请求额外记录以下步骤；旧记录只展示当时采集的内容，不生成虚构补录。

1. 页面提交：原始输入、知识库、模型、检索配置、带入的历史与续写标志。
2. 服务端接收：记录已通过字段验证、登录/访问控制和预算检查，不把此前验证耗时冒充实测。
3. 模型选择、历史裁剪（12 轮 / 24000 字符）及查询改写；无历史时跳过改写模型，失败时记录降级。
4. 路径判断：读取人才表结构与行数，尝试本地规则或模型规划，校验字段/运算符。
5. 人才路径：全表筛选、字段排序、跨表分页、缺失指标处理、来源绑定、程序生成结果；明确跳过向量、片段召回、独立精排和回答生成模型。
6. 普通知识路径：可选查询 Embedding、本地词项向量化、读取活动且权限可访问的候选片段、排除过期索引、向量矩阵缓存、稠密余弦分数、词项余弦分数、归一化权重融合、按分数排序和 Top K。记录选中片段的分数分解。当前没有独立 Cross-Encoder / LLM 精排，标记为未执行。
7. 可选联网检索 / 全表统计、证据与引用编号、模型上下文组装。
8. 每次真实模型调用的参数、消息、返回文本、成功/失败、耗时和 Token。查询 Embedding 记录输入文本和返回向量；后台批量索引不额外复制大批向量日志。
9. 首次输出、流式分块数、字符数、停止/失败、最终输出。续写只记录本次新增文本。
10. 浏览器收到响应头、首段文本、读取结束及 Vue 更新完成。通过响应头 `X-Agent-Trace-ID` 关联，客户端时间相对本次发起请求计算；不与服务端时间线混排或相加，也不作为服务商计费数据。回传失败不影响问答。

模型调用按 `call_id` 合并到已有时间线节点；旧记录缺少对应节点时仍展示其调用明细。最终答案使用安全 Markdown 渲染，支持表格。


### 查询意图分流

明确的本地筛选规则和分页计划可直接执行；其余人才表问题由同一次模型调用识别意图并生成计划，不再用“领域/人才”等关键词决定路由。意图包括 filter、aggregate、semantic、document、clarify 和 unsupported。语义和文档意图进入现有片段混合检索；识别失败不会盲目降级成向量检索来回答统计问题。

aggregate 支持 count、distinct_count、group_count，可附带 AND 筛选条件。按完整非空字段值（去除首尾空白）统计，多值单元格不自动拆分，跨表不按姓名去重；平均值、求和和复杂组合仍需明确提示暂不支持。统计结果由程序生成，记录来源与统计口径；任何已知读表失败或目标字段缺失都会阻止输出全库统计结论。时间线默认展开“查询意图与路径”和“查询未执行”。
