# 人才结构化入库

现有「人才库-900」的 `社区MVP人才池-900.xlsx` 已按原表导入 `backend/knowledge_base.db` 的 `talents` 表：906 条记录、35 个业务字段。存在两组同名记录，按原始行分别保留，不按姓名合并。

使用 SQLite 数据库工具打开数据库，浏览 `talents` 即可查看每条完整记录。常用字段：`name`（姓名）、`organization`（当前机构）、`position`（当前职务）、`biography`（简介）、`education`（教育经历）、`work_experience`（工作经历）、`contact_clues`（联系方式线索）、`domain`（领域）。全部中文表头与数据库字段的对应关系在 `backend/app/services/talent_import.py` 的 `FIELDS` 中。

每条记录保留 `source_id`、`sheet_name`、`source_row`，可追溯到原始文件。`raw_data_json` 保存全部原始字段值及空值，`formulas_json` 保存原表公式（本次 1,270 个链接公式）；业务列以文本保存，避免强制转换原始指标或日期文本。链接公式的显示值和公式分别保存。

```sql
SELECT name, organization, position, location, domain, source_row
FROM talents
ORDER BY source_row;

SELECT t.*
FROM talents t
JOIN knowledge_base_sources bs ON bs.source_id = t.source_id
JOIN knowledge_bases b ON b.id = bs.knowledge_base_id
WHERE b.name = '人才库-900'
ORDER BY t.sheet_name, t.source_row;
```

导入程序只接受当前原表的完整 35 列布局。先预检，再写入：

```sh
cd backend
.venv/bin/python scripts/import_talents.py --source-id 8c1fc583-e065-42f8-a370-151fe302232b
.venv/bin/python scripts/import_talents.py --source-id 8c1fc583-e065-42f8-a370-151fe302232b --apply
```

写入前通过 SQLite backup API 备份至 `backend/storage/backups/`。来源文件、工作表和行号构成唯一键；相同数据重复导入跳过，已有数据发生变化则报错并回滚，不覆盖人工编辑。表结构由 `TalentModel` 和迁移 `0003_talents` 管理。
