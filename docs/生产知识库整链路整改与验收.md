# 人才知识库：整链路整改与验收

整改日期：2026-11-17，最终验收：2026-11-18。范围为当前单机 Docker 部署的人才知识库，覆盖导入、切片、向量生成、召回、条件执行、会话、问答、发布和故障处理。本文区分已实现能力、实测结果与仍未达到的目标；不把单组样例通过等同于生产 SLA。

## 1. 排查结论

截图的零结果不是“没有向量”那么简单，而是多处规则互相冲突：

| 环节 | 排查发现 | 本次处理 |
| --- | --- | --- |
| 意图 | “中科院从事AI4S”曾被本地规则整体当作主题，机构条件未独立执行 | 本地只接受完整可验证的命令；复合表达进入带类型的语义槽位编译，字段白名单校验 |
| 实体 | 中国科学院、中科院、CAS 等没有一致的匹配口径 | 可审计别名表，保留原文引用，英文缩写有单词边界，排除 Case Western 等子串误命中 |
| 数据 | 旧数据库保存的是旧提供方的向量；人才搜索另有一份 bge 摘要缓存 | 统一以数据库中的当前代际、逐人逐字段向量为依据；旧摘要仅作受限迁移兼容 |
| 切片 | 通用导入按整段记录切；人才摘要每字段最多450字、总计6000字 | 按人员和字段形成完整子切片，长字段继续分块，不再用摘要截断替代索引 |
| 召回 | dense 已召回，但随后按字面主题过滤，语义候选全部被丢弃 | 原文主题标签与语义证据两条准入路径；相似度只做召回排序 |
| 逻辑 | 模型扩展的多个召回词可能把复合条件放宽成任意词匹配 | 扩展词只用于召回；直接准入只认明确原词或登记的等价主题，否则核验原文 |
| 上下文 | 国家变更、名单/统计/资料解释切换、这些人/本页容易混用 | 分离任务、条件、结果集合范围和分页；服务端保存可校验快照 |
| 问答 | 解释某人时可能重新检索整个知识库 | 姓名完整匹配，所有片段通过 ChunkTalent 归属限定；同名先消歧 |
| 重建 | 不完整写入可能影响正在使用的索引 | 可恢复的暂存文件 + 全部成功后的事务切换；失败保留已发布索引 |
| 资源 | 一次加载大量向量JSON、多个并发加载器不适合当前1GB容器 | 流式读取、float32、单加载器、有限缓存/队列/向量数量；新增数据源与模型维度的数据库索引 |

## 2. 向量如何拆分

一行人才记录是父记录；其身份、机构、字段原值、源文件、sheet、Excel 行号保存在结构化数据中。研究方向、简介、成果、项目、经历等是子文档。新增的公开业务字段也会索引；不只认固定的几列。

每个子切片重复简短的姓名、当前机构和字段名，再附该字段原文。默认总长约480字符，同字段连续切片重叠最多80字符；重叠不跨人、不跨字段。身份前缀占用块长预算。每片只归属一个 Talent ID，仍保留 Source ID、chunk 序号以及人员的原表行位置。联系方式、账号密钥、证件、操作记录和运营备注等列按字段名从模型输入中排除；这不是自动识别任意正文中的隐私，导入内容仍需要管理。

示例：一个人有较长简介、两段成果和项目记录，会产生多个简介块、成果块和项目块；不会与下一位人才拼成一个向量。姓名和当前机构不再依赖随机落在某一块中。

向量使用部署配置中的 `bge-m3`，配置维度1024；返回数量、索引顺序、维度、有限数值、非零范数均校验后才发布。官方模型说明参见 [BAAI/bge-m3](https://huggingface.co/BAAI/bge-m3)。实际服务是否与官方权重一致，仍由模型服务维护方保证。

源索引指纹包含解析/切片版本、长度、重叠、模型地址、模型名、维度和可选权重版本。替换同名模型权重时，应修改私有配置文件的 `AGENT_EMBEDDING_REVISION`，触发新一代索引，避免混用旧向量。只改一个字段时，其他内容哈希相同且模型指纹兼容的块复用旧向量。

当前是本项目自己的数据库和派生缓存，重建不会删除或修改其他项目的索引，也不会调整共享模型权重。会调用同一个 embedding 服务，因此采用单后台任务、每批最多8条和批间暂停；共享服务仍应由服务端设置各项目配额。

## 3. 检索及回答链路

1. 校验会话用户和知识库访问范围，只加载已授权且有效的资料。
2. 将表达编译成任务与槽位：当前机构、当前所在地、教育/工作经历、姓名、指标、研究主题等。字段必须来自实际表头；未知的机构国家不能靠模型猜。
3. 先执行可以精确执行的结构化条件；人数和指标比较扫描完整结构化范围，不从向量 top-k 推算总人数。
4. 研究主题并行进行 BM25 与子切片 dense 召回，以 RRF 融合；按 Talent ID 合并同一人的块，保留最相关片段用于证据。
5. 全部原文标签直接命中单独保留，不被 dense 的候选上限挤掉。间接语义候选每次最多2人、每人最多500字符证据核验，输出受限的候选 ID、状态、原文片段编号。未引用真实片段、格式错误或超时都记为 unknown，不伪装成“明确不匹配”。复合条件必须联合满足。
6. 名单回答由已选记录生成，附 Record 来源；资料解释按选定 Talent ID 检索其子块，再生成带 Chunk 引用的回答。未写明的成果不补造。深度调研文档的链接文字可索引，链接正文不会自动下载；需显式导入。
7. 快照存全部已匹配结果及未完成候选，分页沿用同一快照，不重新规划，不重复 embedding。快照绑定用户、数据库、知识库及源版本，10分钟过期，最多16份且总计16MB；过期的“这些人”要求重新检索，不自动扩到全库。

原文标签命中代表资料明确标注，不等于外部事实核查。模型语义核验也不能证明事实绝对正确；它提供可检查的原文依据。资料内容本身的质量和更新仍是独立责任。

## 4. 会话语义

- 任务：名单、count/distinct/group统计、资料解释。
- 条件：机构、地域、主题、数值上下限等；追加与同槽位替换有不同语义。
- 范围：当前全库筛选、上一批全部已匹配结果、上一页实际展示记录。
- 展示：排序、用户总量上限、分页大小和偏移。

只说“改成美国”继续原统计或解释任务；明确“查找美国人才”才切换为名单。改变国家不丢主题，取消主题不丢国家，不允许把 h-index 下限覆盖成引用数下限。

“本页”先把上一页人员 ID 集合固化，再在这个集合内筛选；先改成美国得到零条，再改回英国仍能回到同一批人的英国记录，不会因为上一轮零结果而丢掉基准集合。语义判断已确认的人，在主题不变时可复用其证据；后续统计不会退回只计字面标签。

修改旧条件或任务要核对当前原话，歧义保留状态并提出具体澄清。程序本身可完全证明的国家替换无需额外模型审查；其余变更保留有限的语义审查调用。

## 5. 索引生命周期与故障恢复

后台任务把完整新切片及向量写入 `data/index-staging` 的权限受限文件。每批落盘，可在进程重启或明确重试后续传。全部齐备后，在一个数据库事务内检查资料修订号、替换 chunks/向量/归属关系、更新 indexed revision、完成任务。任何失败回滚；处理中发生编辑则放弃过期结果并重新排队。完成或取消的暂存文件会清理，失败暂存受时间及容量限制。

启动时只为使用中且未删除的知识库检查修复；同一代失败任务不无限自动重试。先看任务错误，修复上游后通过现有任务重试入口重试。旧模型向量、归档或未挂载资料不会因此次操作被全盘删除。

派生 NumPy 缓存不是真实数据源，可以重建。缓存按资料和模型代际区分，原子写入，限制大小和时效；正文仍在 SQLite。单次本地向量索引默认上限32768条，超限降级并记录诊断，不能把降级当作成功语义检索。

发布仍执行 `bash deploy/deploy.sh backend`：构建、上传校验、备份、数据库迁移、替换后端和健康检查。模型私有配置不进镜像、不提交 Git。数据库当前迁移为 `0009_retrieval_indexes`，新增字段和查询索引保持旧程序可读取。回滚镜像需先停止写入并确认迁移兼容；若恢复数据库备份，会丢失备份后的写入，不能自动恢复覆盖。

## 6. 验收与性能

测试包括：真实 API 请求及源表独立对照、HTTP/SSE 契约、跨用户快照拒绝、机构别名子串误匹配、复合条件、真假引用、上游超时、同名消歧、人员资料追问范围、统计与分页、取消/编辑/失败后的事务保护、断点恢复、单字段向量复用、模型/维度响应校验。

线上真实数据核对：主人才库906条，当前机构包含中国科学院/中科院/CAS等明确别名的36条，其中7条在核查的研究字段中明确出现AI4S等价标签。原截图问题和英文同义问法均找回这7条，且机构条件独立生效；不是只检查 HTTP 200。所在地原字段中英国9条、美国181条，接口统计与独立 SQLite 查询一致。另有14条所在地不明，界面明确披露，不能当成不存在。

性能以当前 qwen3.8 服务、当前单机、顺序请求为条件。第一轮实测：结构化查询约0.1—0.16秒；统计约2秒；需要模型的复合检索约2—6秒；某次范围变更12.7秒；生成式资料问答约8秒。100条大页会尝试语义核验，耗时不能与默认5条首屏混用。第一轮核验批次的超时触发了进一步缩小批次和输入、收紧复合条件的整改。最终测量见下。

这些数字不是 P95，不代表并发压测结果，也未证明所有任务5秒内。5秒以内是尽量达到的用户体验目标，不能为了时间把未知结果说成零。需要以线上阶段耗时持续评估模型吞吐、证据判断超时率、首屏延迟、准确率和召回覆盖。

### 最终核对及复现

- 全量索引检查：5个有效数据源全部处于当前指纹/修订；31,789条切片全部具备 bge-m3 1024维向量。1,923条人才记录都有切片归属；另有53条普通文档切片无需绑定人员。源切片数分别为1,968、52、14,884、1、14,884，全部匹配，没有进行原始人才删除。
- 数据库执行计划此前为 `SCAN e`，扫描向量正文所在表；补齐模型维度覆盖索引后为 `SEARCH e USING COVERING INDEX ix_chunk_embeddings_model_dimension`。同时增加 `(source_id, chunk_index)` 索引。在线补索引后服务通过健康检查，索引纳入正式迁移，重复迁移安全。
- 存在一次启动检查超时触发自动回滚，补齐数据库查询索引后重新发布成功。当前发布方式仍是单容器停启，发布期间存在短暂停机，不能称为零停机发布。
- 代码回归：250项，249通过、1项跳过。运行 `cd backend` 后执行 `.venv/bin/python -m unittest discover -s tests`，不依赖付费或线上模型。
- 真实模型诊断进程使用同一数据库、请求准备链路、模型和修复后核验模块：向量覆盖906/906，融合方式 BM25+dense+RRF；两条不含原始标签完整字面表达的语义查询，直接命中均为0，但分别获得1名、2名有原文引用的语义确认人员，引用长度分别201和359/372字符。首次耗时5.66和4.56秒；重复请求为1.61和0.38秒。重复结果包含规划/证据缓存收益，不能当作首次请求耗时。
- 模型偶尔返回带 Markdown 围栏的 JSON，现仅规范化这一明确传输包装，重复字段、重复候选、越界引用、无依据的肯定/否定仍拒绝。失败不会把候选判为不存在。

最终服务接口复测：默认5条首屏下，原截图问题共确认7条原文标签命中、显示5条及来源，重复耗时0.227/0.146秒（已受规划缓存收益影响）；两条语义改写分别在4.999/4.626秒返回1/2条带原文证据的结果。浏览器验证了原问题、原始Excel行来源和下一页，第二页除已有直接命中外还纳入有证据的语义候选，未重复第一页面记录。

运维入口 `scripts/build_talent_search_index.py --base-id ...` 已改为提交同一持久后台任务，删除了按人员限长摘要直接调用 embedding 并生成第二套索引的旧路径。历史 `--batch-size` 参数兼容接收，但资源限制统一由后端配置决定；不再以它绕开后台批次上限。

代码及正式迁移已发布到 companyOps，发布版本及最终健康核对见本文末尾。可使用既有 `backend/scripts/benchmark_talent_search.py` 对授权用户的 trace 显式加 `--live` 重放并记录召回状态；它会调用真实模型并写用量记录。业务黄金集应单独维护原始记录ID及人工标注，不能用同一模型生成标签再评估自己。

## 7. 仍需明确的生产边界

当前完成的是单机、当前数据量下的正确性及故障隔离整改。SQLite、单 worker、内存快照不提供多实例共享状态或高可用；主机和模型服务都可能成为单点。若要求严格5秒 P95、多租户并发 SLA 或更大语料，应以业务标注集和压测结果决定扩容、共享会话存储及持久向量检索服务；本次没有未经评估引入额外付费设施。

别名表只登记有依据的等价关系，不随意扩充机构地域推断；其来源见 [中国科学院章程](https://www.nssc.cas.cn/xxgk/gzzd/zkyzc/202111/t20211126_6272430.html) 和 [AI for Science 研究综述](https://arxiv.org/abs/2503.05822)。业务仍需维护标准机构、所在地缺失值及人才资料质量，并建立人工相关性标注集。自动化契约测试能够阻止逻辑回退，不能取代这部分业务验收。
