## 5 秒目标的实际差距

大多数确定性查询和混合召回在本次样本中远低于 5 秒，但**复杂冷查询和追加条件追问尚未达到目标**。
不能用重复请求命中缓存后的 0.17 秒来宣称复杂查询普遍满足 5 秒。

两次慢请求中，`qwen3.8` 规划调用分别花费 10,402 ms 和 10,422 ms；输入约 1,674 / 1,894 Token，输出 264 / 263 Token。
复杂查询的文本与向量召回阶段约 104 ms，其中实际向量调用约 92 ms。
因此当前瓶颈在模型生成查询计划，不在 906 人的向量矩阵计算，也不在向量服务吞吐。
这些是整次模型调用耗时，没有进一步拆分服务排队、prefill 与逐 Token 生成，不能凭一个样本断定具体推理阶段。

建议将目标定义为「有效首屏结果」而不是 SSE 连接建立、心跳或“正在搜索”提示。
同样，不能通过简单把超时改成 5 秒、删除难处理条件、返回空结果等方式伪造达标。

## 推荐路线

你的方向适合这个项目，但应把“理解查询”和“执行查询”分开：复杂表达也可能只需结构化执行，简单主题也可能适合混合召回。

### 1. 固定表头先建立字段字典与确定性执行器

将当前机构、当前地域、职务、各项指标、教育经历、工作经历分别建模，使用稳定 field_id、类型、别名、允许运算符和来源证据。
尽量复用现有机构、地域等字段；数值指标明确区分缺失、未知和 0，不能通过字符串大小比较排名。

明确的机构/地域/指标/排序查询直接执行结构化过滤、排序和分页，不调用模型、不计算查询向量。
全库排名和总数必须对授权后的完整候选范围计算，不能先 Top-K 召回再宣称“全库第一”或“精确总数”。

906 人的规模目前内存扫描已经很快，没有证据要求立刻更换数据库。
数据增长或并发增大时，再把常用结构化字段落到具备索引的类型化列或关联表；保留原始字段用于展示、追溯和迁移。

### 2. 复杂表达只生成最短的可执行计划

LLM 不生成 SQL、不生成名单，只输出允许字段、运算符、值以及排序/分页。
由于表头固定，可以使用短字段 ID 与紧凑操作符，避免每次重复长字段名、解释、无用别名及完整计划。
例如可将“追加当前机构条件”表达为一个追加操作，而不是重新输出上一轮所有主题和字段。

这一阶段的优化目标是减少输入和输出 Token，尤其是当前约 264 Token 的规划输出。
先在独立样本验证紧凑协议的准确性与完整消费能力，再设置适当输出上限。
单纯缩短 max_tokens 可能截断 JSON，不能作为修复。
若压缩协议后仍慢，需要分别测排队和模型推理，再决定是否使用更快的规划模型；不应未经验证改变主回答模型。

### 3. 混合检索只处理需要语义的部分

先执行授权与机构/地域/数值等硬条件，再针对研究主题做 BM25 + bge-m3 并行召回，使用 RRF 融合。
每个人使用一条人才级向量，避免长简介的多个切片占满 Top-K。
本次索引已遵循人才级组织，当前规模的本地矩阵足够小，不需要为了这一步新增外部向量数据库。

相似度是候选依据，不是事实证明。
当前搜索对主题保留了直接词项/别名证据门槛，可减少相邻学科误入，但也可能漏掉未覆盖的同义表达。
如要放开纯语义结果，应建立独立人工标注集和可靠的候选准入/证据核验，明确显示待确认项，不能直接把相似度阈值当事实准确率。
复杂事实如“创业经历”“产业落地能力”尤其不能仅凭通用关键词或模型生成的词表就保证成立。

### 4. 上下文保存条件状态，不从旧回答推导筛选范围

保存条件、排序、知识库/资料版本、用户权限及结果快照。
“其中”“再加”对上一轮条件做追加；“改成”“去掉”“重新开始”使用明确的替换、删除或重置操作。
权限或资料变化时重新校验，不能复用不属于当前用户的缓存。

优先把有完整结构的追问（例如“其中当前机构为 X”）安全地编译为条件增量，而不是总交给模型重述完整计划。
排序和下一页直接复用已授权结果快照，这两条在本次样本中已分别达到 48 ms 与 39 ms。
不能为了快把难以理解的追问当作新问题丢弃原条件；有歧义就澄清。

### 5. 程序输出人才结果，生成模型只负责必要解释

搜索结果表、计数、排序和来源由程序生成，避免再多调用一次模型“润色”名单。
用户明确要求综合评价或解释时，可在稳定的结果集合上额外生成分析，并区分检索结果完成时间与分析生成完成时间。
当前人才搜索已经主要使用程序化结果，因此应该先优化规划路径，而不是对最终表格做流式动画来掩盖等待。

## 建议的下一步验收

1. 先补充泛化的结构化追问增量执行，覆盖不同机构、指标、地域和组合，不能只针对本次样例写规则。
2. 用更紧凑的规划协议做独立 A/B 评估，同时检查字段、逻辑、否定、缺失值及上下文继承是否正确。
3. 准备至少覆盖真实请求分布的独立样本；分别报告结构化、主题混合、复杂规划、上下文四类的冷/热 P50、P95、成功率、正确性和降级率。
4. 增加预期并发下测试，报告共享 LLM 和向量服务负载；真实 5 秒目标应预留网络及页面渲染预算。
5. 将简单路径的目标定为约 1 秒以内，复杂规划尽量留在约 3 秒内，为检索、网络和界面保留余量。这是下一阶段预算，不是本次已经达到的结论。

本次仅重建索引并完成实测和方案评估，没有擅自替换模型、修改查询语义、删除资料或大改生产查询流程。
