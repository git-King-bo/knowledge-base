# 知序 · 知识工作空间

Vue 3 + TypeScript + FastAPI + SQLite 的单服务器团队知识库产品。围绕「建立知识库 → 导入与切片 → 检索验证 → 引用问答 → Token 监控」组织工作流程。

## 产品模块

- **知识库**：创建、编辑、标签、搜索、归档、恢复与删除；库内批量导入资料、查看处理错误、预览切片和重建向量索引。
- **检索测试**：指定知识库、调整 Top K（1–12），查看命中片段、来源与相关度。
- **知识问答**：选择模型服务，流式生成带来源的答案，支持停止及继续生成，保留部分内容；支持按需补充联网搜索、Markdown、代码高亮。
- **Token 监控**：输入、输出、缓存命中、总用量、调用次数、失败数、耗时、覆盖率、按日趋势和模型分布；按 1/7/30/90 天、服务、模型、类型、知识库筛选，明细分页和 CSV 导出。
- **模型配置**：新增/编辑兼容服务、切换默认服务、连接测试和模型试用。

独立文档编辑和分类模块已移除，资料统一放在知识库中。旧文档数据表保留以避免丢失原有数据，但不再提供对应界面和 API。前端没有伪造数据或离线演示回退。

## 登录与生产化改造

已加入登录、角色及知识库授权、模型密钥加密、SHA-256文件复用、持久后台导入、人才管理、历史会话、回收站和备份恢复。实施清单、部署与验证边界见 [生产化实施与验收](docs/production-implementation.md)。

首次启动生成管理员 `admin`，密码保存在 `backend/storage/security/initial-admin-password.txt`（0600权限）。登录后请修改密码。已有数据库可运行 `cd backend && .venv/bin/python scripts/prepare_production.py` 备份并初始化，脚本不调用付费模型。

```bash
cd backend
python -m venv .venv
source .venv/bin/activate
pip install -e .
# 可将 .env.example 复制为 .env 并配置模型
APP_PORT=8001 python run.py
```

```bash

pnpm install

```

## 模型、检索与导入

人才查询采用记录级渐进执行：查询计划区分字面/数值约束、语义条件、召回表达、排序与总量上限。字面约束决定候选范围；BM25 和向量只决定优先核验顺序，不删除低相关候选。带数值排名的查询直接按完整候选范围排序后核验，避免从相关性 Top K 中误选“最高”。纯语义条件、普通列表和语义条件统计共用执行器 `backend/app/services/talent_execution.py`。

普通人才搜索直接返回程序确认的结果和稳定分页，不在回答中加入“回复继续”一类操作提示。严格核验模式仍按批推进并保存进度；资料不足、调用失败、尚未处理、明确不符分别计入覆盖状态，统计未穷尽或仍有未知记录时仅报告已确认数量。`result_limit` 表示用户要求的前 N 名，`talent_page_size` 独立控制分页。接口返回 `talent_coverage`，流式接口放在 meta 事件中。

查询快照绑定用户、知识库及资料版本，当前为单进程内存存储，空闲 10 分钟过期；进程重启、资料变更、快照被容量淘汰时需重新查询。它不是跨进程持久任务队列。自动导入 worker 启动时检测人才切片归属缺失并排队修复，保留人才 ID 与原始字段；修复可能重新生成向量，沿用现有模型配置。失败任务通过已有任务重试入口处理。未启用 worker 时不会自动修复。

离线复现（不调用外部模型、不修改本地业务数据）：`backend/.venv/bin/python backend/scripts/audit_talent_retrieval.py`。业务回归覆盖规模边界、零结果续查、完整范围排名、分页、语义统计、索引修复与权限/版本隔离；这些测试验证执行契约，不代替真实模型的语义质量评测。

可在模型配置页面添加服务，也可在 `backend/.env` 首次初始化默认服务：

```dotenv
AGENT_DEFAULT_API_URL=https://your-provider.example/v1
AGENT_DEFAULT_API_KEY=your-key
AGENT_DEFAULT_MODEL=your-model
AGENT_EMBEDDING_API_URL=https://your-provider.example/v1
AGENT_EMBEDDING_API_KEY=your-key
AGENT_EMBEDDING_MODEL=your-embedding-model
APP_KB_CHUNK_MAX_CHARS=480
APP_KB_CHUNK_OVERLAP_CHARS=80
```

模型服务初始化后，页面保存的地址、模型和默认服务选择会保留；环境密钥用于环境默认服务未单独保存密钥时的回退。Mock 仅用于本地连通性验证。

资料支持 TXT、Markdown、PDF、DOCX、XLSX、CSV、JSON，每份最多 20 MB；扫描 PDF 需先 OCR。XLSX 会读取所有非空工作表，保留工作表名和行内单元格顺序；公式读取文件中缓存的计算结果，不执行重算，含公式的文件请先在 Excel 中计算并保存后上传。旧版 XLS 需另存为 XLSX 或 CSV。解析及索引在持久后台队列中完成，返回任务信息；可查看进度、取消及失败重试。已授权且处理版本相同的重复文件直接复用。缺少向量化配置时使用词法检索；向量化调用失败时记录失败并回退到词法检索。归档知识库不会参与检索。

XLSX 总数类问题会额外读取当前知识库的原始工作簿，按工作表提供完整行数统计，不受检索切片数量限制，已上传文件无需重新导入。首个非空行为包含“姓名”等字段的表头时，统计姓名非空的记录数及不同姓名文本数；同名不代表同一身份，记录数不等于按身份去重的人数。当前统计不执行按部门等条件筛选，也不跨文件合并去重；原文件缺失时明确无法确认总数。

资料列表的“预览”可查看文件内容：XLSX/CSV 每页展示 50 个非空行、原始行号，XLSX 支持工作表切换；最多展示前 200 列，超出时给出提示。PDF 使用浏览器原文预览；DOCX、TXT、Markdown、JSON 展示分页正文文本，DOCX 不保留原始排版。预览独立于检索切片，接口校验资料与当前知识库的关联。

联网搜索沿用 `WEB_SEARCH_ENABLED`、`WEB_SEARCH_PROVIDER`、`WEB_SEARCH_API_KEY` 等配置。未配置或搜索失败时，回答仅使用可用的知识库来源。

人才 XLSX 查询保留完整人员行与列名，按领域、机构等字段筛选，并支持明确来源的数值指标排序，例如“具身智能领域按 OpenAlex h-index 排名前20”。常见领域及指标查询直接执行，其他条件由当前模型生成受字段白名单约束的查询计划（检索测试使用默认模型），程序执行 AND 筛选及数值排序，不运行生成代码。自然语言规划会额外计入一次模型调用。缺失或非数值指标不参与排名；展示数量遵守页面召回数量 Top K（默认5），所有文件合计不超过该上限；问题要求更少时取更小值，附全表命中数、缺失数和原始行号。各文件独立统计，排序后统一限制展示数量，现有文件无需重新导入；OR、分组等暂不支持的复杂条件会要求明确查询。

## 流式问答

`POST /api/knowledge/ask/stream` 使用 fetch 接收 SSE，依次返回 `meta`（来源）、`delta`（正文）和 `done`（用量）；中途失败返回 `error`。模型服务需支持兼容 OpenAI 的流式接口和 `stream_options.include_usage`，未报告的用量保持未知。原非流式接口保留。停止或中断后可在原回答下点击「继续生成」，沿用原模型、问题和来源快照，将已生成正文作为 assistant 上下文发起新请求，新增内容接到原回答；每次续写单独记录实际用量。这是模型续写请求，不能恢复供应商已取消的连接。

知识问答支持本次页面会话内的连续追问：切换菜单、模型或知识库保留对话，点击「清空会话」后下一问不再携带旧上下文。登录用户的会话会保存到服务器，可从历史会话入口恢复、收藏和提交反馈。

`/ask` 和 `/ask/stream` 接受可选的 `history: [{question, answer}]`。前端只发送最近最多 12 轮已完成的问答，每轮问题最多 5000 字符、回答最多 6000 字符，合计最多 24000 字符；后端再次限制总长度。历史仍显示在界面中，但超出窗口的内容不会全部发给模型。停止或失败的回答可「继续生成」，完成前不进入后续问答的历史。

有结构化人才查询状态的追问，将上下文理解与查询规划合并为一次调用，完整保留上一轮条件供模型判断继承或重置；有完整结果的单纯排序继续复用快照。文档问答及无结构化状态的追问保留独立改写。切换知识库清除上一库条件。上下文解析失败时明确提示，不拼接旧答案执行含糊查询。所有实际模型调用仍计入用量，分页复用已确认结果。

前端通过 `setApiHeaders(() => ({ Authorization: 'Bearer app-session' }))` 设置动态公共请求头；`streamKnowledge(payload, { headers, signal, onMeta, onDelta })` 支持单次覆盖及取消。应用会话请求头与后端模型 API 密钥分开管理。

正文先缓冲，再由 `requestAnimationFrame` 每帧最多解析一次完整 Markdown 快照。未闭合标记随后续内容补全，代码高亮在结束时执行。原始 HTML 转为文本，最终 HTML 经过 DOMPurify 白名单清洗；链接限 HTTP/HTTPS，Markdown 图片显示为链接，Chunk/Web 引用保留点击定位。

## Token 统计口径

- 模型适配器返回 `ChatResult(content, usage)`；问答、模型试用及每批向量化请求都会保存调用记录。
- 用量来自服务响应的 `usage`。只在输入和输出都已报告时相加补齐缺失的总量，不按文本长度推算费用或用量。
- 缓存命中属于输入 Token，不再加入总量。
- 原有日志缺少用量时显示未知；Mock 和失败且未返回用量的请求也不计入已报告 Token 总量。
- 汇总与图表覆盖筛选范围内全部记录，明细分页不会截断汇总。时间以 UTC 存储，按浏览器本地时区划分日期。
- 切片中的本地词元估算用于内容处理，与模型实际消耗不同。
- 平台统计本项目发起的调用，不是整个供应商账户账单；联网搜索服务的额外费用和货币成本不在统计范围内。

## 数据库与验证

默认数据库为 `backend/knowledge_base.db`。启动会增量创建缺失表，不回填历史用量、不删除旧数据。

支持 MySQL 5.7+，安装后端依赖后，在 `backend/.env`（Docker 使用 `deploy/production.env`）填写
`XINIU_MYSQL_HOST`、`XINIU_MYSQL_PORT`、`XINIU_MYSQL_DATABASE`、`XINIU_MYSQL_USER`、`XINIU_MYSQL_PASSWORD`。
密码仅放在环境配置中，不提交代码仓库，不放在 Vercel 前端变量中。

- `APP_DATABASE_MODE=auto`（默认）：启动时探测 MySQL，连接或认证失败则使用 SQLite；未配置 MySQL 时直接使用 SQLite。
- `APP_DATABASE_MODE=mysql`：强制 MySQL，失败拒绝启动；适用于运维迁移和不允许切库的正式部署。
- `APP_DATABASE_MODE=sqlite`：强制 SQLite，适用于本地测试。
- SQLite 地址优先使用 SQLite 类型的 `DATABASE_URL`，否则读取 `APP_SQLITE_FALLBACK_URL`。
  本机默认 `sqlite:///./knowledge_base.db`；Docker 中设为 `sqlite:////data/knowledge_base.db`。
- 选择仅发生在进程启动时。运行中断线不会切换到另一套数据库；再次启动会重新选择。
  两套数据库的数据、账号和会话互不自动同步，本地旧数据不会自动导入 MySQL。
  迁移、表结构及业务 SQL 错误不会被当作连接失败吞掉。
- MySQL 模式仍需持久化上传目录和加密主密钥，SQLite 回退文件也必须位于持久卷。
  当前仍按单实例、单导入 worker 运行，换成 MySQL 不代表已经支持多副本。

```bash
# 在 backend 目录执行，只检查连接和结构，不启动应用或创建表
.venv/bin/python scripts/check_database.py

# 已有兼容 MySQL 表但没有本项目迁移版本时，先停写，再执行接管
# 自动备份本项目现有表到 storage/backups/*.sql.gz，补齐缺失表并扩容长文本
# 遇到字段或主键不匹配会停止；不删除已有记录，不修改无关表，不导入 SQLite
APP_DATABASE_MODE=mysql .venv/bin/python scripts/prepare_mysql.py

# 强制隔离到 SQLite 运行回归测试，避免本地 MySQL 配置影响测试
APP_DATABASE_MODE=sqlite .venv/bin/python -m unittest discover -s tests -v
```

管理员 `/api/operations` 的 `database` 字段可查看当前库类型（不返回凭据）。
MySQL 的备份请使用数据库备份工具，另外备份上传文件和主密钥；页面备份入口、
`backup_workspace.py` 和 `maintenance.py` 原有流程只支持 SQLite，MySQL 下不能直接使用。
`prepare_mysql.py` 的 SQL 快照是结构调整前的保护措施，恢复到独立空库时可用
`gzip -dc 备份.sql.gz | mysql --host=地址 --port=端口 --user=用户名 --password 新库名`，
交互输入密码。它不包含原始上传文件、加密主密钥，也不替代定期完整备份。

全新数据库可使用 `alembic upgrade head`。如果已有数据库由旧版应用自动创建且从未使用 Alembic，应先备份并确认与 `0001_initial` 的四张旧表一致，再执行 `alembic stamp 0001_initial` 和 `alembic upgrade head`。不要直接对已有未标记数据库执行首个建表迁移。

```bash
cd frontend
npm test
npm run build

cd ../backend
.venv/bin/python -m unittest discover -s tests -v
```

当前按单服务器、单团队部署，包含知识库级授权、持久后台任务和密钥加密。公网启用前必须完成真实域名、HTTPS、模型出站白名单、备份与目标环境负载验收；不支持直接以共享 SQLite 横向扩容。

### 人才查询性能与运行边界

- 全表缓存以数据库、用户、知识库、源文件更新时间和索引 revision 为键；每次请求先做权限与版本检查。120 秒 TTL，最多 16 项且总序列化大小不超过 32 MiB；返回独立副本，编辑结果不会污染后续查询。不缓存读取失败的资料。仅加载检索需要的数据库列。
- BM25 分词结果按实际文本内容哈希缓存，最多 16 项 / 32 MiB / 300 秒。查询向量按服务地址、模型、凭据指纹和查询文本哈希缓存，最多 256 项 / 8 MiB / 300 秒。密钥不写入缓存键明文或日志。
- 合法查询计划按模型配置、用户、知识库、资料版本、当前问题、上一轮问题和计划、规划契约缓存，最多 256 项 / 2 MiB / 120 秒。逐人核验缓存按模型配置、用户、知识库、原始字段全文、问题、条件和核验契约隔离，最多 2048 项 / 8 MiB / 120 秒；只有通过 schema 与原文引用校验的明确判断可以复用。超时、格式错误、虚构证据和资料不足不缓存。不跨相似问题猜测复用；更换条件、资料或模型后重新核验。
- 查询向量默认读取超时 4 秒、连接超时最多 2 秒；401/402/403 冷却 300 秒，其他失败冷却 30 秒。冷却期直接使用文本检索；恢复时每进程允许一个探测，其余请求直接降级。更换模型或密钥立即形成独立状态。批量导入仍使用原有 60 秒读取超时。HTTP 超时是各网络阶段的超时，不是整次请求的绝对截止时间。
- 独立核验批次在剩余调用预算内合并为一波，最多并行四路。数据库 Session、用量预留与日志结算仅在请求协调线程使用；网络线程不持有数据库会话或请求上下文。调用前串行预留预算，按提交顺序结算用量，保留原来每次操作最多 4 次模型调用的限制；单批失败不覆盖另一批已确认结果。小于等于 6 人的显式总量要求不做多批预取。所有候选和不确定性仍按原规则保存，无法核验不等同于不符合。
- `APP_TALENT_PARALLEL_VERIFICATION=false` 可恢复串行核验；`APP_TALENT_COMBINED_PLANNING=false` 可恢复独立追问改写。`APP_STRUCTURED_MODEL_TIMEOUT` 默认 20 秒；`APP_EMBEDDING_QUERY_TIMEOUT` 默认 4 秒；`APP_EMBEDDING_FAILURE_COOLDOWN` 默认 30 秒；`APP_EMBEDDING_DENIED_COOLDOWN` 默认 300 秒。
- 缓存、熔断和已有分页快照均为进程内状态，重启后重建；多实例各自维护缓存，分页仍需粘性会话。没有引入跨实例共享预算或全局熔断。每个实例的网络并发上限随原有请求并发限制最多扩大为四倍，部署时应按模型服务商配额设置 `APP_MODEL_CONCURRENCY`。本次没有改变 SSE 协议，仍在当前页核验完成后返回结果。
- 可在执行轨迹查看全表缓存、词项索引缓存、查询向量缓存和熔断状态。应分别监测冷/热缓存、首屏耗时、各阶段耗时、降级率、未核验数量和模型 Token，不用单个测速样本宣称 P95 达标。

同一知识库内的人才追问采用条件增量合并：新增领域默认保留已有地域、机构、经历与排序，新增主题与旧主题并且；明确切换主题才替换旧主题。规划器通过 `context_update` 显式取消/替换旧条件，并引用当前用户原话；程序校验引用、条件下标与合并后计划；删除、主题替换或重置需要单独一次语义核对，不能通过省略字段无声删除条件，也不通过动词白名单判断语义。核对失败或歧义时不执行变更。重置需要明确重新开始的表达；切换知识库不继承旧计划。执行轨迹记录合并后的实际条件。计数继承筛选条件，但不把原来的排序或前 N 名当成人口范围限制。

### 语义能力与执行正确性的验收分开

`test_talent_conversation.py` 中的固定回复是 API/分页流程的模拟模型，只验证给定结构化计划如何执行，不能作为模型理解未知表达的证据。历史故障样例用于防止回归；`test_talent_context_update.py` 另外使用固定随机种子的 120 组不透明标签组合验证条件合并的不变量，不依赖任何真实领域词或命令动词。

真实模型评估独立运行，不进入免费离线单元测试。`tests/evals/context_semantics.json` 保存输入和预期的结构化行为，可通过 `--cases` 换成独立维护的未见样本；生产代码不读取该评估文件。执行方式（在 backend 目录，显式授权实际模型调用，每个样例最多两次）：

```bash
PYTHONPATH=. .venv/bin/python scripts/evaluate_context_semantics.py --live --provider-id YOUR_PROVIDER_ID --output /tmp/context-evaluation.json
```

评估报告分别保存规划输出、语义复核结果、实际合并计划、断言、耗时与用量；任何一项失败返回非零退出码。当前样本覆盖条件增加/删除/替换、主题交集、否定、歧义与跨语言重置。小样本通过不代表未知语义全部正确，也不代表端到端召回率；模型、提示契约变化后应使用独立的新样本复评，并把生产误差按意图识别、计划编译、召回、证据核验分别归因，避免只增加示例问题对应的分支。

语义复核只接收合并前后的规范化条件集合、排序和用户总量上限，不把增量计划当完整状态，也不把每页大小当用户筛选条件。重置时排序/总量上限必须有本轮引用依据，否则程序清空；引用本身仍需经过语义核对。评估同时区分“正确完成”“阻止执行/要求澄清”“执行了错误条件”，不把拦住错误但未完成查询统计成语义正确。

### 普通人才搜索（默认）

`APP_TALENT_FAST_SEARCH=true` 时，普通找人使用一次结构化规划、并行 BM25/查询向量、人才级聚合、元数据筛选、加权 RRF 和稳定分页。默认不调用生成模型逐人核验，也不再调用生成模型生成表格。原文检索依据由程序附上；无法可靠编译的事实条件明确列为未核验，不能冒充满足条件。多个并列主题默认取并集；显式交集与跨轮新增条件保留 AND。国家／城市拆出 `@current_region`，未知字段不作为否定依据；当前地域不会使用教育经历推断。

执行顺序为：授权与资料版本检查 → 本地结构化编译 → 必要时固定规划模型 → 结构化过滤 → BM25/向量并行召回 → 直接主题依据准入 → 融合/可选 Rerank → 程序化表格。简单机构、当前海外、明确任职经历、单一字面主题、机构加主题、精确指标排序和分页由本地编译，完整识别后才执行；包含额外条件、未知地域、含排除/范围/多主题逻辑或歧义指标时整体交给规划模型，不能只执行已识别的一部分。排序追问直接重排绑定用户、知识库和资料版本的完整结果快照，不重新规划或召回。

机构关系具有固定字段边界：无历史措辞时只查当前机构；校友、历史任职、当前或历史任职分别绑定教育经历、工作经历、当前机构+工作经历。关系以当前问题中的原文为依据，教育或简介中的普通提及不能证明任职。结果顶部显示当前生效条件；跨轮新增条件与已有条件取交集，明确重置、删除或替换才改变旧条件。

复杂查询规划可通过 `APP_TALENT_PLANNER_PROVIDER_ID` 和 `APP_TALENT_PLANNER_MODEL` 固定服务；留空时使用系统默认服务。用户切换普通回答模型不会改变人才查询计划。当前本地默认服务为用户配置的 `qwen3.8`。规划超时或计划无效返回 503/502 并在轨迹中记为失败，不再伪装成成功澄清或“没有人才”。

主题搜索最多保留 `APP_TALENT_SEARCH_CANDIDATES` 条候选（默认 60）。指标排序作用于这个召回集合，缺指标排后；不宣称全库精确排名或精确人数。`search_mode=hybrid` 快照翻页不重新召回、不调用模型。API 请求可显式使用 `talent_search_mode=verify` 进入原来的严格核验路径；语义精确统计仍使用严格路径，并报告未完成范围。`APP_TALENT_FAST_SEARCH=false` 可整体回退。

主题结果准入与候选召回分开：规划中的 `values` 只允许原主题和严格等价的别名/翻译，`related_values` 存放相关学科或技术，仅扩展候选召回。原始业务全文（包括个人简介、代表成果）必须包含各主题组的直接词项依据，才能进入正式结果；这一步在候选截断、指标排序和分页前执行。向量近邻和 Rerank 排名本身不证明领域归属，不能把 Top-K 填满的候选数当匹配数。直接证据召回有独立名额，避免被大量泛化候选挤掉。

目前没有经过校准的纯语义准入模型，因此只有语义相似、没有直接主题或别名依据的记录不进入正式结果；该保守策略可能遗漏未覆盖的同义表达。`retrieval.unsupported_candidates` 记录本次召回但未准入的数量，便于后续使用独立标注集评估召回损失。词项命中也不是对复杂关系或否定语境的事实核验，此类需求应走严格核验路径。2026-10-12 的“查找托卡马克领域人才”线上记录曾错误返回 60 人，原因是泛化词和向量近邻被直接当作结果；此缺陷已加入通用回归测试，不按人名或具体领域硬编码修复。

向量正文加载在有界后台线程中完成，每个线程拥有独立数据库 Session；请求只用已经就绪的矩阵。首次冷加载、超时、缺少兼容索引时返回文本搜索并明确提示。缓存按数据库、模型/地址、授权来源及资料版本隔离，120 秒更新；返回前仍按授权人才 ID 和当前筛选条件限制。查询向量默认 1.5 秒超时、不重试；降低延迟不能解释为向量服务已经可用。应分别统计 `vector_status`、覆盖人数、首屏耗时、规划调用数和命中率。

推荐在服务所在机器构建完整的人才级索引：

```bash
cd backend
PYTHONPATH=. .venv/bin/python scripts/build_talent_search_index.py --base-id <知识库ID> --batch-size 16
```

索引位于 `storage/search-index`，以资料内容、模型、地址和数据库的摘要区分版本。每人一条向量；资料全文仍用于 BM25 和引用，向量文档按业务字段限长，不包含联系方式。批次有检查点，可使用较小批次重跑；所有人员成功且资料版本未变化后才原子发布，旧服务向量不被覆盖。资料或模型改变后需重建；未找到当前版本的人才索引时，后台可加载同模型的已有分块向量并按人才聚合。多实例需共享或分发索引目录；分页快照仍是进程内状态，需要粘性会话。部署前须统一各实例的模型和后台任务配置，不能让旧实例继续消费新模型的导入任务。

可选 Rerank 配置完整地址 `AGENT_RERANK_API_URL`、密钥、模型和超时。适配器发送 `{model,query,documents,top_n}`，要求响应 `{results:[{index,relevance_score}]}`；最多重排 60 条、每条 800 字，失败或索引异常保留融合顺序，未配置则完全跳过。这个环节不是通用生成式 LLM 核验，也不会凭空新增人员。

真实请求回放（会产生模型调用费用，取已有 trace 的用户/知识库/模型配置）：

```bash
PYTHONPATH=. .venv/bin/python scripts/benchmark_talent_search.py --live \
  --trace-id <已有请求ID> --repeat 3 --output /tmp/talent-search-benchmark.json
```

报告区分文本降级和向量实际参与，重复请求验证缓存。5 秒是性能目标，不是固定保证；冷启动、模型延迟和并发 P95 必须分别实测，不能把未使用向量的耗时当成完整混合检索成绩。

查询向量使用规划合并后的主题和严格等价别名，不再预计算、复用整句找人命令的向量，避免“查找人才”、地域与排序措辞干扰研究主题。规划结束后查询 embedding 与 BM25 并行，查询超时默认 1.5 秒且不重试；元数据查询不计算 embedding。人才矩阵在规划期间预热。该依赖顺序优先保证查询含义一致，不能承诺冷查询总耗时固定小于 5 秒。
